# Руководство администратора

Администратор входит под своей учётной записью и попадает на страницу «Состояние».

## Состояние системы

Обновляется раз в 5 секунд: база данных и время отклика, нагрузка процессора, память, свободное место на диске, активные сессии, идущие занятия, ошибки сервера за последний час, последняя резервная копия, какие модели ИИ подключены. Красная рамка — повод вмешаться.

Проверка для внешнего мониторинга без входа: `GET /api/health` → `{"ok":true}` (данных не раскрывает).

## Пользователи

- Создание учётной записи: логин, ФИО, роль (администратор, преподаватель, обучающийся), пароль по политике — не короче 8 символов, буквы и цифры. Обучающегося можно сразу **добавить в группу** — без группы он не попадёт на занятие. В таблице видно, в каких группах ученик (оранжевое «без группы» — ещё ни в одной) и какие группы ведёт преподаватель.
- Блокировка и разблокировка. Заблокированный пользователь сразу теряет все сессии.
- Смена пароля. Все сессии пользователя завершаются.
- После 5 неудачных входов подряд учётная запись закрывается на 15 минут (настраивается в `.env`: `MAX_FAILED_LOGINS`, `LOCK_MINUTES`). Срок сессии — `SESSION_HOURS`.
- На демо-стенде (`DEMO_MODE=true`) демо-учётки защищены от блокировки и смены пароля, чтобы проверяющие не мешали друг другу.

## Группы

Раздел «Группы» — все группы центра: создать группу и назначить преподавателя, переименовать, добавить и убрать учеников, убрать группу в архив и вернуть. Преподаватель видит только свои группы и сам ведёт их состав; сменить преподавателя группы может только администратор. Подробно — [teacher.md](teacher.md), раздел 6.

## Журнал аудита

Каждое значимое действие записывается: входы и неудачные попытки, блокировки, изменения пользователей и настроек, группы и их состав, подтверждение и правка оценок преподавателем (было → стало), резервные копии, ошибки сервера. Фильтры по событию, пользователю и датам, выгрузка в CSV для Excel.

Журнал хранится не меньше 6 месяцев: срок задаётся в настройках, но ниже 183 дней система его не опускает. Старые записи удаляет встроенный планировщик раз в час.

## Резервные копии

- Автоматически каждый день в заданное время (по умолчанию 03:00), хранятся заданное число дней (по умолчанию 14).
- Вручную — кнопка «Сделать копию сейчас».
- Формат — `pg_dump` custom, каталог задаётся `BACKUP_DIR` (в Docker — том `backups`).

Восстановление выполняется из консоли сервера, когда не идёт занятие:

```bash
# Docker
docker compose exec app sh scripts/restore.sh /backups/trainer-2026-09-27T03-00-00.dump
# без Docker
DATABASE_URL=... scripts/restore.sh backups/trainer-2026-09-27T03-00-00.dump
```

Кнопки восстановления в интерфейсе нет намеренно: случайный клик не должен стереть идущее занятие.

## Настройки

Нормативы (30 с на ответ ДДС, 3 мин на отработку, таймер набора карточки 112, 48 ч до «Не завершено»), срок хранения журнала, время и срок хранения резервных копий. Каждое изменение пишется в журнал. Адреса моделей, база данных и параметры входа задаются при установке в `.env`.
