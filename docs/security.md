# Безопасность и персональные данные

Тренажёр работает в изолированном контуре учебного центра. Он обрабатывает ФИО обучающихся и преподавателей, результаты обучения и — при голосовых звонках — голос обучающегося: речь распознаётся в текст, сама запись не сохраняется. Это персональные данные по 152-ФЗ, поэтому защита заложена в устройство системы, а не добавлена сверху.

## Доступ

| Мера | Как сделано |
|---|---|
| Вход по логину и паролю при каждом входе | Сессия хранится в базе, в браузере — только случайный токен в cookie `HttpOnly`, `SameSite=Lax`, `Secure` при HTTPS. В базе лежит не сам токен, а его SHA-256 |
| Парольная политика | Буквы и цифры, длина — из политик доступа (8–32 символа, по умолчанию 8); пароли хранятся как bcrypt-хеш |
| Защита от подбора | После N неудачных попыток подряд учётная запись закрывается на M минут (по умолчанию 5 и 15, администратор меняет в пределах 3–20 и 1–1440), каждая попытка пишется в журнал |
| Истечение сессии | По политике доступа (1–72 ч, по умолчанию `SESSION_HOURS` = 10); при блокировке пользователя или смене пароля все его сессии удаляются сразу |
| Политики доступа | Администратор меняет их в настройках только в безопасных границах; значения вне границ сервер не примет ни из формы, ни из базы, ни из `.env`. Каждое изменение — в журнале (было → стало). На демо-стенде демо-учётки не блокируются, сессия не короче 4 ч, ночной сброс возвращает значения по умолчанию |
| Роли | Администратор, преподаватель, обучающийся. Каждая страница и каждый API-запрос проверяет роль на сервере — страница сама, не полагаясь на общий каркас раздела (тест-инвентарь `tests/admin-guard-inventory.test.ts` не пропустит страницу или API администратора без проверки); обучающийся видит только свои результаты, преподаватель — свои занятия |
| Публичные адреса | Без входа доступны только страница входа и `GET /api/health`, который не отдаёт никаких данных |
| Загрузка файлов | Материалы и файлы билетов загружают только преподаватель и администратор. Файл до 20 МБ, вся библиотека — не больше `MATERIALS_MAX_TOTAL_MB`. Тип проверяется по расширению и по содержимому: PDF, DOCX, XLSX, PPTX, TXT и картинки; HTML, SVG, программы, подмена расширения, документы с макросами и встроенными программами не принимаются. На диске файл лежит под именем, которое придумал сервер, путь не выходит за каталог. Отдаётся с `Content-Disposition`, `X-Content-Type-Options: nosniff`, без кэша и — кроме PDF — в песочнице (`Content-Security-Policy: sandbox`). Каждое скачивание проверяет, кому виден материал: чужой отвечает «не найдено», аноним — 401. Файл билета только читается и не сохраняется. Тесты — `tests/materials-access.test.ts`, `src/lib/files/files.test.ts` |
| Сервер в контейнере | Работает от непривилегированного пользователя, пишет только резервные копии, файлы материалов (том `materials`) и кэш; миграции при старте — один раз от администратора контейнера |

## Журнал аудита и сбоев

Входы и неудачные попытки, блокировки, изменения пользователей, настроек, политик доступа и сценариев, загрузка и удаление материалов, подтверждение и правка оценок преподавателем (кто, когда, было → стало), пуск и остановка служб, резервные копии, ошибки сервера. Системный журнал показывает отдельно события самой системы: ошибки и запуски сервера, копии, проверки целостности, пуск и остановку служб, ночной сброс стенда. Журнал хранится не меньше 6 месяцев, выгружается в CSV. Подробно — [admin.md](admin.md).

Ежедневный контроль целостности проверяет базу, миграции, полноту справочников, свежесть и читаемость резервной копии и свободное место; проблема — красный баннер у администратора и запись в системном журнале.

## Шифрование

Внутри класса трафик идёт по HTTPS через Caddy с собственным центром сертификации (`tls internal`), на публичном стенде — с сертификатом Let's Encrypt. Без HTTPS браузер не даёт микрофон, поэтому голосовые звонки работают только в защищённом канале. База данных доступна только с самого сервера: порт 5442 привязан к 127.0.0.1, пароль задаётся в `.env` (`POSTGRES_PASSWORD`). На сервере с HTTPS приложение тоже закрывается от сети (`APP_PUBLISH=127.0.0.1:3000`): снаружи открыт только Caddy на портах 80 и 443.

## Модели ИИ и данные

- В контуре все модели (языковая, распознавание и синтез речи) ставятся локально, данные не покидают сервер. Адреса моделей — настройка, а не код.
- Администратор может выключить модели на ходу («Состояние» → «Службы»): ни один запрос к моделям не уходит, работают правила и голоса браузера.
- На демо-стенде используется облачный API. Туда уходят учебные реплики вымышленных заявителей, тексты карточек из билетов и — в голосовом режиме — речь того, кто работает на стенде, для распознавания. Реальных вызовов 112 в системе нет. В контуре учебного центра облака нет: те же функции выполняют локальные модели.
- ИИ не выставляет итоговую оценку: он готовит черновик, оценка идёт в зачёт только после подтверждения преподавателем.

## Резервные копии и восстановление

Ежедневная копия базы по расписанию и ручной запуск, вместе с копией файлов материалов; хранение N дней; восстановление из консоли одной командой — база и файлы. Подробно — [admin.md](admin.md).

## Соответствие 152-ФЗ и 149-ФЗ

- **Цель обработки** — обучение и аттестация персонала. Состав данных минимальный: ФИО, логин, роль, результаты попыток и текст реплик учебных разговоров. Аудио не хранится: фрагмент речи живёт только до распознавания. Библиотека материалов — для методичек и инструкций; персональные данные слушателей в неё не загружают.
- **Место обработки** — сервер учебного центра в РФ. Внешних передач нет, кроме облачной модели на демо-стенде.
- **Доступ** ограничен ролями, все действия журналируются.
- **Удаление** — администратор блокирует учётную запись. Записи журнала аудита хранятся установленный срок, затем удаляются автоматически.
- Оператор данных — учебный центр, он оформляет согласия слушателей по своему локальному акту. Система даёт для этого технические меры: разграничение доступа, журнал, шифрование, резервное копирование.
